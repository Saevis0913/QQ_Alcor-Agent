Alcor Agent 0.3.2-as.5 · RC2 收发验证包（Windows x64）

本包适用两种经过校验的 as.5 文件组合：原版安装和保留本次开发机模型功能的版本。更新器只替换 7 个 Agent 程序文件，另写一份版本标记，沿用机器上已有的 Alcor 服务。未签名，供作者安排现场验证。请先解压全部文件。

1. 双击「01-检查.cmd」，选择包含 Alcor Agent.exe 和 runtime 的安装根目录。输出 stock-as5 表示原版，audited-as5 表示已核对的现役基线。出现不匹配时请把提示交给作者核对。检查可以在程序运行期间执行。
2. 从系统托盘正常退出 Alcor Agent，并正常退出该安装目录运行的 Alcor 服务。双击「02-安装RC2.cmd」选择同一根目录。看到“已安装 RC2，提交后 7/7 文件校验通过”后，按平时方式启动。再次运行「01-检查.cmd」可确认状态 RC2。程序包版本号仍为 as.5。
3. 需要回退时，正常退出程序，双击「03-回退.cmd」。成功时恢复这 7 个目标在安装前的字节内容，移除新增程序文件和版本标记，保留使用过程中产生的聊天及数据。
4. 正在运行时，双击「04-现场核对.cmd」选择安装根目录。原上报机可在安装前和安装后各做一次，每次会生成新的两条测试文字。用同一测试会话，在 60 秒内从手机发入站文字一次，再从 Agent 聊天存档页给手机发出站文字一次。即使界面提示失败，也请先核对手机。若错过窗口，重新开启核对并使用新标记。请另外记下桌面 QQ 是否看见入站、Agent 出站提示（含错误码）和手机实际收到几条。
5. 控制台最后一行是 JSON 报告的位置，默认在本机临时目录。请把该文件和三项人工观察交给作者。只包含随机测试标记、时间、健康状态、事件计数与标记命中条数。工具只读本机回环 /health 和相应数据目录，只写新的核对报告；工具本身不发送消息。

读数方法
• 有效双向样本：桌面 QQ 和 Agent 各看到同一入站一次；inbox.inbound 和 archive.inbound 各有一条有效 ID；Agent 发送成功、archive.outbound 有一条有效 ID，手机恰好收到一条。inbox 和 archive 是同一入站的两个存储位置。
• samples 中 serviceBound 为 null 表示未取得明确布尔值。events 是所有核心事件的总数，即使增加也不能单独证明这条消息被处理。eventDelta 为 null 表示样本数不足、采样失败或计数无法跨样本比较。matches 中 complete 为 false 时，rows 是已读文件的命中下限。
• 桌面 QQ 已收到但事件增量为零、双处均无标记时，保留同时段报告和运行版本。事件有增加但 Agent 未入档时，另查公开事件交付与 Agent 存档。Agent 有有效回执但手机未见或出现两条时，另记手机观察与消息时间。
• 默认读取安装目录的 data，识别当前环境 ALCOR_AGENT_PROFILE 和 ALCOR_AGENT_DATA_DIR。自定义数据目录也可以运行："<安装目录>\runtime\node.exe" "<解压目录>\observe.mjs" "<安装目录>" --data "<实际数据目录>" --seconds 90。可选 --report "<新文件完整路径>"。与 Agent 同一配置有助于避免核对到别的实例。

安装条件与限制
• 更新器使用 Windows x64 的 .NET Framework、本地支持文件事务的卷和该安装目录的正常写入权限。程序仍运行、文件被锁、基线未知或系统无法提交事务时会报错。可先执行「01-检查.cmd」核对目录状态，把完整错误码反馈给作者。
• 此包覆盖 Agent 的收发回执、存档与跨重启防重逻辑。既有模型接入取决于安装前所用基线。原上报机的 Windows build 22000 仍需上述实机验收。
