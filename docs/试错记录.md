# Alcor Agent 试错记录（2026-11-11 → 2026-11-17）

按「现象 → 根因 → 处理」记，只留能复用的部分。每条都能在提交历史或 `docs/` 里找到对应代码。

## 打包 / 安装器

1. **`RELEASE_VERSION_MISMATCH`**
   `package.json` 改了版本，`package-lock.json` 顶层与 `packages[""]` 两处没跟着改，`stage-release.mjs:174` 直接抛错。
   → 每次改版本要一次改四处：`package.json`、`package-lock.json`（两处 `"version"`）、`src/environment-check.mjs`、`installer/Alcor-Agent.iss` 的 `#define ReleaseVersion`。

2. **ISCC `Source file "...\release-{#ReleaseVersion}\payload\runtime\node.exe" does not exist`**
   Inno 预处理器不会对 `#define` 里的 `{#…}` 二次展开。
   → `Build-Release.ps1` 显式传 `/DReleaseVersion=` 与 `/DPayload=`，iss 里用 `#define Payload "..\artifacts\release-" + ReleaseVersion + "\payload"`。

3. **`Copy-Item : 路径中具有非法字符`**
   `Build-Release.ps1` 与 `INSTALLATION.txt` 没有 UTF-8 BOM，PowerShell 5.1 按 GBK 读中文 → 乱码进路径。
   → 这两个文件必须带 BOM；`edit` 工具写入会丢 BOM，改完补 `\ufeff`。

4. **ISCC `You may not specify more than one script filename`**
   MSYS 把 `/DReleaseVersion=…` 当成路径改写。
   → 调 `ISCC.exe` 或安装包一律加 `MSYS2_ARG_CONV_EXCL='*'`。

5. **静默安装 `Runtime error (at 60:2164): List index out of bounds (0)`**
   静默模式没有向导窗体，代码却还在访问控件与 `RunList.Checked[0]`。
   → `CheckEnvironment` / `CurPageChanged` / `NextButtonClick` / `CurStepChanged` 四处加 `WizardSilent` 守卫。

6. **`check-upgrade.ps1` 打出空的「已退出旧版进程」**
   `$ownersStopped` 只在 try 内初始化，早期异常时 `@($null).Count` 在 PowerShell 里等于 1。
   → 脚本级初始化 + `.Count` 判断。

7. **安装器退出码 5、且没写日志**
   上一次 setup 进程还没退出就再起一个，单实例互斥直接失败。
   → 等几秒或确认进程退出再跑；重试即可通过，不是包的问题。

## 运行时 / 核心

8. **`QQ_LOGIN_NOT_CONFIRMED`（面板写「尚未确认 QQ 登录」）**
   三处 identity 断言把「服务对象被别的框架占着 / 宿主刚装载 / 真没登录」全塌成一个码；原生侧只有 `LB_HOST_NO_SESSION`。
   → 细分 `ALCOR_HOST_PRESENT` / `FOREIGN_MODULES_PRESENT` / `IDENTITY_REQUIRES_CONNECTION`，并做 3×200ms 有界重试。

9. **`STARTUP_OR_CONFIG_ERROR`**
   `listen.token` 少于 16 个可见 ASCII 字符直接被拒。
   → 手写配置时用 ≥16 字符令牌；正常安装由 Agent 首启生成。

10. **原生 relocation 测试找不到目录**
    `test/native-relocation.test.mjs:14` 默认指向 `artifacts/native-release`，实际构建输出在 `artifacts/native`。
    → 改默认值，或设 `ALCOR_NATIVE_ARTIFACT_DIR`。

## 界面

11. **整页发紫，改 CSS 不生效**
    真正生效的是 `interface.css` 的组件令牌层（`--section-*`、`--control-*`、`--selected-surface`…），旧值全是紫灰。
    → `redesign.css` 第十三节把这些令牌整体重映射，而不是逐个组件覆盖。

12. **改了 CSS 页面没变**
    Chromium 对同名 CSS 走内存缓存。
    → 每次改完把 `index.html` 的 `redesign.css?v=N` 递增。

13. **聊天白名单填了不保存**
    保存分支还在按旧分区 id 判断（`if (sec === 'allow')`），设置合并成栏目后条件永不成立。
    → 改成按栏目取子分区集合 `inSec('allow')`；另加「保存名单」按钮 + 回车 + 失焦保存。

14. **模型管理抽屉左栏被压成 90px**
    `.model-modal-left` 有 `max-width:40%`，在 236px 的网格列里只剩 40%。
    → `max-width:none` + 显式 `grid-template-columns:236px minmax(0,1fr)`。

15. **抽屉一滑就卡**
    `.model-modal-overlay` 上有 `backdrop-filter: blur(2px)`，每帧整屏高斯模糊。
    → 改 `none`；阴影从 80px 收到 34px；过渡只留颜色/边框/位移。

16. **框选看不到高亮**
    浏览器默认淡蓝在深色底上几乎不可辨。
    → `::selection` 改黄铜 `color-mix`（正文 46%、输入框 62%），`caret-color` 同色。

17. **顶栏眉标把标题顶出可视区**
    `body` 网格首行固定 88px。
    → 眉标 8.5px + 标题 23px + 说明 11.5px 挤进同一行。

18. **插件行「停用」下划线拖出一截**
    `.mcard-toggle` 有 `min-width` 与 flex 拉伸。
    → `min-width:0; width:auto; flex:0 0 auto`，并提高选择器特异性压过 `.mcard-acts .btn`。

## 表情审核

19. **「表情未通过审核，未收藏」，原因却写「信息不足」**
    `normalizeReview()` 要求三项全 `clear`，`uncertain` 被当成违规。
    → 改为「只有 `present` 才拦」，`uncertain` 放行；提示词同步说明「拿不准就返回 uncertain，会放行」。

## 记录导出（codex 任务存档）

20. **`write() argument must be str, not dict`**
    `session_meta.base_instructions` 是对象 `{text, provenance}` 而不是字符串。
21. **`dict contains fields not in fieldnames: 'at'`**
    CSV 表头与写入字段不一致，多写了一个 `at`。
22. **`compactions.txt` 膨胀到 77MB**
    `compacted.replacement_history` 是巨量重放历史。
    → 摘要正文与索引分开写，完整记录另存 `compactions-raw.jsonl`。
23. **时间戳显示成 `1794369150`**
    生命周期字段是 epoch 秒，要 `datetime.fromtimestamp(v, UTC)`。

## 环境

- 本机 MSYS 没有 `sha256sum` / `chmod` / `iconv` / `od`，也没有 `python`；校验与文本处理一律用自带 `runtime\node.exe`。
- `shutdown.exe` 直接调会被 MSYS 参数改写破坏 → 走 `powershell.exe -NoProfile -Command "& shutdown.exe /s /t 90"`。
- 预览服务单实例锁：重复起会报「已有 Alcor Agent 实例在运行（PID …）」，必须按端口找 PID `taskkill //F`。
- 附件目录里的截图是只读，复制出来前先删同名或改权限。

## 24 · 模型 API 报 HTTP 401，界面只说「本轮未提供原因分析」

- 现象：运行错误框显示 `HTTP_401`，下面一整段提供商原始 JSON（`Authentication Fails, Your api key: ****f561 is invalid`），原因一栏写「本轮未提供原因分析」，看起来像程序 bug。
- 根因：`resources/app/src/session-effects.js` 的 `errorCode()` 只从文本里抠 `HTTP_<status>` 和原生错误码，401 被原样透出；而 `session-diagnostics.js` 的模型原因分析只在「存在工具调用报错」时触发，本轮是模型请求本身失败，所以永远不会补原因。
- 处理：`errorCode()` 增加三条确定性判定 —— 认证类 → `API_KEY_INVALID`、额度类 → `API_QUOTA_EXCEEDED`、模型不存在 → `MODEL_NOT_AVAILABLE`（`httpStatus` 401/402 同样归入）；`orchestrator.js` 失败收尾时给这三个码写入固定中文原因（`errorReasonSource='local'`），面板据此不再加「模型推测」前缀。
- 验收：`test/api-error-classification.test.mjs` 3 例通过；全量 368（367 通过 / 1 跳过 / 0 失败）。

## 25 · 私聊发已收表情 400 / 收藏表情收不到（2026-11-17 18:3x）

- 现象：`OneBot send_private_msg HTTP 400: NATIVE_STICKER_SOURCE_UNAVAILABLE`；收藏时 `当前会话的消息没有可收藏的 QQ 表情`。
- 根因一：核心 `native-core/received-sticker.mjs:20` 只处理「有 QQ 市场来源」的已收表情，私聊/无来源一律抛 `NATIVE_STICKER_SOURCE_UNAVAILABLE`；`src/native-backend.mjs:203` 的单图段只要 file 形如 `alcor-media-…` 就走这条路径，于是连「重发收到的普通图片」也会 400。
- 根因二：Agent `resources/app/src/native-stickers.js:79` 只收带 `sticker` 标记的项，而该标记依赖 QQ 段的 `sub_type==1`/`emoji_id`，普通图片永远收不进来。
- 处置：核心在该错误码下改为取缓存图 URL → fetch 字节 → `prepareOutgoingImage` 当普通图片发出；Agent 收藏时回落到同消息普通图片，并区分 `STICKER_MESSAGE_NOT_IN_HISTORY` 与 `STICKER_MEDIA_NOT_FOUND`；`send_sticker` 去掉 `replyToMessageId`/`atUserId`，守卫改抛 `STICKER_STANDALONE_ONLY`。
- 版本：0.2.2（`ce60f4b6…`），Agent 370 / 核心 255 全通过。

## 26 · 图片仍不能转发 / 图片与表情要共用一条逻辑（2026-11-17 18:5x）

- 现象：v0.2.2 修掉 400 之后用户仍说「图片无法转发」，要求图片与表情共用一套转发、收藏逻辑。
- 根因：工具层根本没有「按消息转发图片」的入口 —— `send_image` 只收 http(s) 直链且要预览门禁，`send_sticker` 只收收藏里的表情 id；模型手里有 `alcor-media-…` 也发不出去。
- 处置：`resources/app/src/native-stickers.js` 新增 `resolveReceivedMedia()`（收藏表情 id / 消息里的图片或表情 / 直接给 file 三种入参）与 `sendReceivedMedia()`；`resources/app/src/sender.js` 新增 `sendForwardedImage()`（图片走正常发图管道，不吃表情档位与配额）；`send_sticker` 增加 `messageId`（明确转发，不受档位限制）；`send_image` 接受 `alcor-media-…` 直接转发；`collect_sticker` 更名「收藏图片或表情」。
- 版本：0.2.3（`1cc8bfc5…`），Agent 371（370 通过 / 1 跳过）。
- 安装踩坑：0.2.3 首次静默安装 `EXIT=5`，日志 `DeleteFile 失败；错误代码 5 … alcor-runtime-<digest>.dll` 被占用 → 回滚并退出；确认 DLL 可改名（已解锁）后重装 `EXIT=0`，四个关键文件与源仓库哈希一致。
