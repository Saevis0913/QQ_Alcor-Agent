# Alcor Agent 关键要点

发布版：**正式版 v0.2.1**（内部版本 0.2.1）。这份是接手或排障时先看的一页。

## 一、装在哪、跑什么

| 项 | 值 |
|---|---|
| 默认安装目录 | `D:\Alcor`（没 D 盘时装到其他本地磁盘，安装器允许改） |
| 程序主体 | `Alcor Agent.exe`（Electron 壳）+ `runtime\node.exe` + `resources\app`（页面与业务） |
| 原生核心 | `resources\alcor\src\main.mjs`，配套 `artifacts\native\runtime\alcor-runtime-<64hex>.dll`、`alcor-host.dll`、`qq-host-loader.exe` |
| 用户数据 | `<安装目录>\data\`（`config.json`、`alcor.config.json`、`sessions\`、`memory\`、`usage\`、`private-message-policy.json`、日志） |
| 插件 / 技能 | `resources\app\plugins\<id>\`、`resources\app\skills\<id>\`（安装包只带内置 9 插件 + 5 技能，用户自建放同目录，升级不删） |
| 默认端口 | 控制台 5310，Agent 本地面板由首启挑选空闲端口并写进 `data\config.json` |

## 二、配置与安全

- `listen.token` 必须 ≥16 个可见 ASCII 字符，否则核心以 `STARTUP_OR_CONFIG_ERROR` 退出。
- 安装包不含 `data` 目录，也不含任何 API Key、管理员 QQ、聊天记录、登录态；`installer/check-upgrade.ps1` 会拒绝清单里任何含 `data` 段的路径。
- `initializeInstall()` 的契约是「只初始化全新配置，已存在的配置/令牌/历史永不覆盖」。
- 私聊不受回复档位影响：未暂停、未被屏蔽、白名单放行就逐条回；每日私聊上限在「私聊规则」里，默认 0 = 不限。
- 表情审核：三项判定里只有 `present`（确实违规）会拦，`uncertain`（信息不足）按放行处理。

## 三、QQ 兼容

- 按 `wrapper.node` 的 SHA-256 精确匹配，不看版本号：
  - 9.9.36-53644 → `0d8b94448f4dafe7337b88d6a568b004224c37fcbe2bd1142c1af7624fbd534c`（已实机）
  - 9.9.37-54395 → `fed532ad58d2404dcedf2858554e8fa52a5f4e65b271c008d2faca4011d7d4a2`（静态适配，待实机）
- 连接失败会区分：`HOST_ALREADY_PRESENT`（本进程已驻留 Alcor 宿主）、`QQ_SESSION_CONFLICT`（别的框架注入残留 → 退出旧框架并重启 QQ）、`QQ_LOGIN_NOT_CONFIRMED`（真没登录）。
- 服务对象校验依赖 vtable 与 transport 指针；QQ 更新后需重新取 RVA 并更新 `native-core/win32/qq_host_backend.c` 与 profile。

## 四、打包与验收（每次发版照抄）

```
# 1. 改版本（四处）
resources/app/package.json            "version": "0.2.1"
resources/app/package-lock.json       顶层 + packages[""] 两处
resources/app/src/environment-check.mjs   standard ? '0.2.2' : '0.2.1'
installer/Alcor-Agent.iss             #define ReleaseVersion "0.2.1"

# 2. 出包（嵌入原生管线，约 150–200 s）
MSYS2_ARG_CONV_EXCL='*' powershell.exe -NoProfile -ExecutionPolicy Bypass \
  -File installer/Build-Release.ps1 -NativeReleaseDir 'D:\Alcor\development\Alcor\artifacts\native'

# 3. 校验
node -e "…"  # 复算 SHA256SUMS.txt 四行；fs.linkSync 建对外别名

# 4. 自检
<安装目录>\runtime\node.exe resources\app\src\environment-check.mjs --root . --install --embedded
```

- 测试基线：Agent `node --test test/*.test.mjs` → 365（364 过 / 1 跳过 / 0 失败）；核心 255/255。
- 装机四检：静默安装退出码 0、自检退出码 0 且版本正确、注册表 `DisplayName/DisplayVersion` 正确、装机自带核心 `/health` 200。
- 安装器 `AppId={{67D615C6-B01A-4880-A0AE-26C0AFC01000}` + `UsePreviousAppDir=yes` → 同目录覆盖即为原地升级。

## 五、环境坑（本机）

- `MSYS2_ARG_CONV_EXCL='*'`：否则 `/VERYSILENT`、`/DName=…` 会被 MSYS 改写成路径。
- 本机 MSYS 无 `sha256sum`/`chmod`/`python`，校验与文本处理用 `runtime\node.exe`。
- PowerShell 5.1 读中文脚本要求 UTF-8 BOM（`Build-Release.ps1`、`check-upgrade.ps1`、`INSTALLATION.txt`）。
- 改前端 CSS 后必须递增 `ui/index.html` 里 `redesign.css?v=N`，否则走内存缓存。
- 预览服务有单实例锁，重启前按端口找 PID 结束进程。

## 六、仓库与发布

- 源码：`D:\Alcor\development\Alcor-Agent`（Agent，主仓）、`D:\Alcor\development\Alcor`（原生核心）。

## 表情库（2026-11-18）

- 索引是纯 JS（Electron 33 / Node 20.18 没有 `node:sqlite`），不要引入 SQLite 原生依赖。
- 路由 handler 必须写响应：`return json(res, 200, …)`；`return {…}` 会让请求永久挂起。
- 这些源文件是 CRLF：改之前 `replace(/\r\n/g,'\n')`，写完再换回，否则 `replace` 会静默不生效。
- 改标签时 `normalizeStickerEntry` 会吃掉 `bytes`/`scope`，`put()` 与 `readDoc()` 都要从上一版补回，否则统计被清零。
- 名称排序用 `localeCompare('zh-Hans-CN')` 正序（拼音 A→Z），日期/大小/使用次数为倒序。
- 达 `sticker.maxEntries` 只停「自动收藏」；手动收藏与发送不受限。

## 打包红线（2026-11-18 用户要求）

- 安装包永远不带 `data/`：配置、会话、记忆、令牌、`data/stickers/` 与 `data/sticker-images/` 都属于运行时数据，`payload` 只从 `resources/` 取。
- 重建打包链路时，`check-upgrade.ps1` 要保留那条守卫：清单里出现含 `data` 段的路径直接判 `Unsafe payload path`。
- 出包前先清空测试表情（`/api/stickers/list` 应为 0 条、`data/sticker-images` 为空），别把自己的测试图带进发布版。
