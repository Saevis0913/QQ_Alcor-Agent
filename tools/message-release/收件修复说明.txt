Alcor 核心收件修复 R1 · Windows x64 · Issue #2 现场候选

适用版本
本包识别原版 Agent as.5 / 核心 0.4.1 和已核对的 as.8 / 核心 0.4.3。更新器逐字节校验已有文件。安装涉及核心中的两个 JavaScript 文件和一个安装标记，沿用当前账号、数据目录和模型配置。包内 EXE 未签名，更新使用支持文件事务的本地卷和目录的正常写权限。

操作
1. 全部解压，运行「01-检查」。选包含 Alcor Agent.exe 和 runtime 的安装根目录。
2. 从托盘正常退出 Agent，并正常退出此目录正在运行的 Alcor 核心。运行「02-安装收件修复」。看到“已安装 收件修复 R1”且两个目标校验通过后，按平时方式重开程序。
3. 核心运行后，运行「04-现场核对」。在 60 秒内用另一个账号向本机发一次窗口里的入站文字，记录桌面 QQ 和 Agent 是否各看见一次。如同时验证出站，从 Agent 聊天存档页向同一会话仅发送一次出站文字，并记录手机收到条数。上报的好友列表 502 可另行记录。核对结束后，窗口显示本地 JSON 路径。
4. 需要回退时正常退出程序，运行「03-回退」。它会校验并恢复安装前的核心文件。未知文件组合会中止；将检查提示反馈给作者即可。

本次修复
核心识别到私聊后会在当前会话立即提交。已提交私聊重放时只发布一次。如果旧会话在等待群资料期间取消了消息发布，新会话可以接收同一消息的重放。群资料查询失败仍交付正文，超时后返回的资料也不会改写已发布消息。采样以接收源提供的业务输入为起点。

报告中的 receiveWindow
• cyclesCompleted 增长、inputs 为 0，表示采样期间接收任务能结束，但没有读到非空业务输入。
• sameCyclePending 为 true，表示从头到尾观察到同一轮任务仍在执行；仅凭这个字段无法区分等待输入与等待处理。
• inputs 增长时可看 parseErrors（解析异常）、unrecognized（未识别消息）、duplicates（重复消息）、staleMessages（旧会话未提交）与 messagesPublished（交给事件发布回调的消息数）。输入包含通知，总数不对应单条测试文字。
• receiveWindow 为 null 表示样本不足、核心未运行此版代码或采样期间更换实例或会话。只记录许可的错误码、计数、时间和随机核对标记。报告无需账号、令牌或聊天截图。
• 通过标准为同一入站在桌面 QQ 与 Agent 各出现一次，对应存档带有效消息 ID；重连后用新标记再核一次。
