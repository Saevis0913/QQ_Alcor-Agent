# Alcor Agent 关键要点

发布版：**正式版 v0.2.1**（内部版本 0.2.1）。这份是接手或排障时先看的一页。

## 一、装在哪、跑什么

| 项 | 值 |
|---|---|
| 默认安装目录 | `D:\Alcor`（没 D 盘时装到其他本地磁盘，安装器允许改） |
| 程序主体 | `Alcor Agent.exe`（Electron 壳）+ `runtime\node.exe` + `resources\app`（页面与业务） |
| 原生核心 | `resources\alcor\src\main.mjs`，配套 `artifacts\native\runtime\alcor-runtime-<64hex>.dll`、`alcor-host.dll`、`qq-host-loader.exe` |
| 用户数据 | `<安装目录>\data\`（`config.json`、`alcor.config.json`、`sessions\`、`memory\`、`usage\`、`private-message-policy.json`、日志） |
| 插件 / 技能 | `resources\app\plugins\<id>\`、`resources\app\skills\<id>\`（安装包只带内置 9 插件 + 5 技能，用户自建放同目录，升级不删） |
| 默认端口 | 控制台 5310，Agent 本地面板由首启挑选空闲端口并写进 `data\config.json` |

## 二、配置与安全

- `listen.token` 必须 ≥16 个可见 ASCII 字符，否则核心以 `STARTUP_OR_CONFIG_ERROR` 退出。
- 安装包不含 `data` 目录，也不含任何 API Key、管理员 QQ、聊天记录、登录态；`installer/check-upgrade.ps1` 会拒绝清单里任何含 `data` 段的路径。
- `initializeInstall()` 的契约是「只初始化全新配置，已存在的配置/令牌/历史永不覆盖」。
- 私聊不受回复档位影响：未暂停、未被屏蔽、白名单放行就逐条回；每日私聊上限在「私聊规则」里，默认 0 = 不限。
- 表情审核：三项判定里只有 `present`（确实违规）会拦，`uncertain`（信息不足）按放行处理。

## 三、QQ 兼容

- 按 `wrapper.node` 的 SHA-256 精确匹配，不看版本号：
  - 9.9.36-53644 → `0d8b94448f4dafe7337b88d6a568b004224c37fcbe2bd1142c1af7624fbd534c`（已实机）
  - 9.9.37-54395 → `fed532ad58d2404dcedf2858554e8fa52a5f4e65b271c008d2faca4011d7d4a2`（静态适配，待实机）
- 连接失败会区分：`HOST_ALREADY_PRESENT`（本进程已驻留 Alcor 宿主）、`QQ_SESSION_CONFLICT`（别的框架注入残留 → 退出旧框架并重启 QQ）、`QQ_LOGIN_NOT_CONFIRMED`（真没登录）。
- 服务对象校验依赖 vtable 与 transport 指针；QQ 更新后需重新取 RVA 并更新 `native-core/win32/qq_host_backend.c` 与 profile。

## 五、环境坑（本机）

- `MSYS2_ARG_CONV_EXCL='*'`：否则 `/VERYSILENT`、`/DName=…` 会被 MSYS 改写成路径。
- 本机 MSYS 无 `sha256sum`/`chmod`/`python`，校验与文本处理用 `runtime\node.exe`。
- PowerShell 5.1 读中文脚本要求 UTF-8 BOM（`Build-Release.ps1`、`check-upgrade.ps1`、`INSTALLATION.txt`）。
- 改前端 CSS 后必须递增 `ui/index.html` 里 `redesign.css?v=N`，否则走内存缓存。
- 预览服务有单实例锁，重启前按端口找 PID 结束进程。

## 表情库（2026-11-18）

- 索引是纯 JS（Electron 33 / Node 20.18 没有 `node:sqlite`），不要引入 SQLite 原生依赖。
- 路由 handler 必须写响应：`return json(res, 200, …)`；`return {…}` 会让请求永久挂起。
- 这些源文件是 CRLF：改之前 `replace(/\r\n/g,'\n')`，写完再换回，否则 `replace` 会静默不生效。
- 改标签时 `normalizeStickerEntry` 会吃掉 `bytes`/`scope`，`put()` 与 `readDoc()` 都要从上一版补回，否则统计被清零。
- 名称排序用 `localeCompare('zh-Hans-CN')` 正序（拼音 A→Z），日期/大小/使用次数为倒序。
- 达 `sticker.maxEntries` 只停「自动收藏」；手动收藏与发送不受限。

## 打包红线（2026-11-18 用户要求）

- 安装包永远不带 `data/`：配置、会话、记忆、令牌、`data/stickers/` 与 `data/sticker-images/` 都属于运行时数据，`payload` 只从 `resources/` 取。
- 重建打包链路时，`check-upgrade.ps1` 要保留那条守卫：清单里出现含 `data` 段的路径直接判 `Unsafe payload path`。
- 出包前先清空测试表情（`/api/stickers/list` 应为 0 条、`data/sticker-images` 为空），别把自己的测试图带进发布版。

## 表情审核与媒体发送（2026-11-18）

- 审核策略：只有画面**明确**出现血腥、猎奇、色情或恶俗才拦；画质差、看不懂、信息不足、普通夸张表情一律放行（`uncertain`）。模型异常、非 JSON、少一行、抽帧失败都只让**那一张**走兜底，不再整单报「无法确认表情审核/标签结果」。
- 兜底行不写缓存，下次仍会重试打标签。
- 收藏落库必须写 `bytes`；旧条目由 `StickerManager.repairBytes()` 按本地文件大小回填。
- 发送能力实测（QQ 9.9.36-53644，核心 `capabilityScope=private-group-text-and-media-receive`）：文本 ✅、图片 ✅、表情 ✅、拍一拍 ✅；**视频 ❌ `VIDEO_NEGOTIATION_UNCONFIRMED`**（宿主未确认视频上传协商，非参数问题，`inspectVideo` 也只收 `base64://`）；语音 ⚠️ 通道在但需要真实 silk 样本，Agent 无发送工具；文件与合并转发只有读取，没有发送动作。

## 先说给谁听：读上下文再开口（2026-11-18）

- `src/prompt.js` 的 `resolveContextTier` 新增两个前置闸门（排在回复策略之前，与档位无关）：`addressedToOther`（@ 了别人且没 @ 我）→ 不接；`stickerOnly`（只有媒体没有文字）→ 群聊当冒泡不接，私聊当提醒必接。活跃期（`warm`）里群聊表情会给一次机会。
- `src/orchestrator.js`：被 @ 或拍一拍后 `#markWarm` 记 8 分钟（`behavior.mentionWarmMinutes` 可调，钳到 30 分钟以内），`#isWarm` 过期即清；`#stickerOnly` 认 `[图片]/[动画表情]/[表情]/[视频]/[语音]` 这类纯占位文本；`#addressedToOther` 认 `atMe===false && atNames.length>0`。
- 提示词新增 `Read First` 段（默认与自定义系统提示词两条路径都注入）：先读上下文确认在跟谁说话、不是对我说的就不接、表情不过度解读、群聊表情=冒泡、私聊表情=提醒/招呼（先补他没被回的问题，没未回就问一句或起话头）。
- 自测（`resolveContextTier` 直接调用）：群 纯文字 → 响应；群 表情冒泡 → 不响应；群 表情+活跃期 → 响应(3 档)；群 @别人 → 不响应；群 @我 → 响应；私聊 表情 → 响应（原因「私聊表情（提醒/招呼）」）；1 档普通闲聊 → 不响应。

## 改 data/config.json 必须整份写回（2026-11-18 事故）

- 症状：内置扩展任务全部 `BUILTIN_MODEL_FAILED`、`0 token`，日志显示「模型:（未设置）」，QQ 里文字和表情都不回。
- 原因：调试 `sticker.maxEntries` 时只把 `sticker` 段写回配置文件，`api.baseUrl/model/apiKey` 被默认值覆盖。密钥本身仍留在 `dshProviderKeys`，所以能恢复。
- 规矩：读整份 JSON → 改字段 → 整份写回；写之前先 `cp data/config.json data/config.json.bak`。恢复后必须看日志最后一行是不是 `模型: <name> @ <baseUrl>`，再用 `POST /api/providers/test-chat` 验一次 200。

## 模型身份不许被空串覆盖（2026-11-18）

- 现象：设置页一次普通保存后 `api.baseUrl` / `api.model` 变空，界面「未选择模型」，所有模型调用回落 `BUILTIN_MODEL_FAILED`。
- 原因：设置页把模型身份三件套放在隐藏字段里整份回传；旧页面 `beforeunload` 的兜底保存读到的隐藏字段是空的，就把空串写进了配置。
- 现在三层防护：UI 侧空值不写（`ui/app/08-modals.js` 的 `api` 补丁只带非空身份字段）；服务端 `src/config.js` 的 `updateConfig` 丢弃「用空串覆盖已有值」的 `api.baseUrl/model`；真要清空必须显式带 `__clearIdentity__`（删除提供商走这条）。

## QQ 连不上时的判定顺序（2026-11-18）

程序**不自带** NapCat / SnowLuma / LiteLoader，只保留了识别它们注入模块的扫描（`resources/alcor/native-core/discovery.mjs` 的 `foreignPattern`）。连不上时按下面的顺序看，不要先怀疑「框架残留」：

1. **核心没在运行** → `CORE_OFFLINE`：先启动 Alcor 核心。
2. **QQ 版本未适配** → `UNSUPPORTED_BUILD`：原生接入按 `wrapper.node` 的 SHA-256 精确匹配，只认 `native-core/qq-profiles.mjs` 里登记的构建（当前 9.9.36-53644 实网验证、9.9.37-54395 静态适配）。QQ 自动更新到新版本后必然连不上，这不是残留。
3. **宿主残留** → `HOST_PRESENT`：上一次注入的 `alcor-host.dll` 会一直驻留到 QQ 退出，重连会被拒绝；要退出 QQ 再登录。
4. **其它框架同时挂在 QQ 上** → `FOREIGN_MODULES`：列出模块名，退出那个框架即可，不用卸载。
5. **QQ 没在运行 / 没登录** → `NO_QQ_RUNNING` / `RECEIVE_NOT_READY`。

排查入口三处共用一份判定（`resources/app/src/qq-diagnosis.js`）：设置 → 连接与桌面 → 「QQ 接入」卡片、底栏状态、随包 `控制台无法连接，显示被占用点这个，对照最后一行判定码.cmd`（`tools/qq-doctor.mjs`，只读，报告写到 `data/qq-doctor-<时间戳>.log`，退出码 0 可连 / 1 需处理 / 2 版本未适配 / 3 核心未运行 / 4 读不到 QQ）。

恢复连接的选择保存在 `data/alcor.config.json.native-resume.json`；「宿主已驻留」不再清掉这份选择，而是每 30 秒轻量重试，等 QQ 重启后自动接上。

## 覆盖升级不能直接删旧文件（2026-11-18）

别人装了旧版之后，把新安装包跑到正在运行的安装目录上，会停在「尝试替换已存在的文件时出错：DeleteFile 失败；错误代码 5」。占用者有三种：`Alcor Agent.exe` 自己、安装目录里的 `runtime\node.exe`（核心子进程）、以及 `QQ.exe` —— 旧版 `alcor-runtime-*.dll` 注入在 QQ 进程里，QQ 不退就一直锁着。

安装器现在的做法（`installer/Alcor-Agent.iss`）：

1. `StopLockingProcesses()` 在 `PrepareToInstall` 与 `CurStepChanged(ssInstall)` 各调一次：先 `taskkill` 掉 `qq-host-loader.exe` 与 `Alcor Agent.exe`；再用 PowerShell 只杀安装目录下的 `node.exe`（按 `ExecutablePath` 前缀匹配，避免误杀系统里别的 node）；`tasklist` 查到 `QQ.exe` 就提示「升级需要先关闭 QQ」并 `taskkill`，连试三次（QQ 会自动重启）。
2. `[Files]` 只剩一条通配，带 `restartreplace`：万一还有进程杀不掉（例如提升权限的实例），Inno 会把它登记到下次重启时替换，而不是中断安装、整单回滚。
3. 静默安装同理：`WizardSilent` 下跳过提示框，直接关 QQ。

实测：对正在运行、QQ 已注入旧 DLL 的 `D:\Alcor` 覆盖安装 → `EXIT=0`、日志 `Need to restart Windows? No`、无 `DeleteFile` 报错；装完 `Alcor Agent.exe` 时间戳已更新，QQ 与 Agent 进程都被关闭（需手动重开）。干净目录安装同样 `EXIT=0`。

## 回复判定：四档 / 被点名不能被策略吃掉（2026-11-18）

**症状**：群聊仍有概率已读不回；滑条拉到四档也不回；@ 了也不回。

**根因（三处，按影响排序）**

1. `src/prompt.js` 的 `replyPolicy` 分支在**档位判定之前**短路：只要配置里有 `store.replyPolicy`（例如 `mode=probability, probability=3`），`contextTier=4` 根本不参与判断 —— 每条消息都按 3% 掷骰子。会话页里那句「未触发回复：概率回复 3%」就是这条路径。
2. 同一分支的 `mentioned` 只认 `atMe === true`：QQ 侧 @ 段解析失败或同名时 `atMe=false`，消息就被当成"没点我"，`mentions` 模式直接静默。
3. 即使通过了闸门，**是否开口由模型决定**：`Read First` 让它"不是对我说的就不接"，读完上下文判断"在聊别的"就沉默，客户端没有任何兜底。

**修复**

- `src/prompt.js`
  - 被点名优先：`atMe === true` 或文本里点到机器人，除 `off` 外一律响应（`被点名（策略不拦）`）。
  - 四档优先：`contextTier >= 4` 且策略不是 `off` → `全部响应（四档优先于策略）`。
  - `mentioned` 判定从 `atMe !== true 才看文本` 放宽为 `atMe !== true 就看文本`（覆盖 `atMe=false` 的误判）。
- `src/prompt.js` + `src/orchestrator.js`
  - `mustReply` = 私聊 / `atMe` / 拍一拍 / 四档；命中时用户提示里插入【本轮必须回复】段。
  - 一轮跑完 `session.sent.length === 0`、没报错、没中止 → 带 `forceReply` 补跑一次（每会话只补一次，`session.forcedReply` 标记），补跑提示语更强。
- `src/conversation-instructions.js`：`Read First` 第 2 条补"例外（必须开口）：@ 我 / 拍一拍 / 私聊，不看参与度风格"，并给出判断依据（@ 段、点名字、接着我上一句）。
- `src/qq-diagnosis.js`：`HOST_PRESENT` 不再让用户"必须退出 QQ 重登"——宿主通常半分钟内自己连回；`RECEIVE_NOT_READY` 同步改成"正在确认账号"。

## 表情库三处修正（2026-11-18 晚）

- **「0 B」不是真的空**：索引行的 `bytes` 早先没写，`fileBytesOf()` 现在直接从 `file://` 指向的本地文件取大小；`put()` 在缺字段时依次回落「入参 → 上一行 → 文件大小」，`openStickerStore()` 打开时还会把历史行与 doc 一起补一遍（`rowBytesFix()`）。实测 9 条 0 B → 全部有真实大小（32.7 KB–3.14 MB）。
- **滚轮翻不动**：`.view` 是 `overflow:hidden`，网格长到视口外就永远看不见。改为 `html[data-theme] #view-stickers { overflow-y:auto; overscroll-behavior:contain }`，滚轮/触控板/键盘都能翻（`redesign.css?v=36`）。
- **QQ 侧缓存过期就再也发不出去**：`alcor-media-…` 句柄在 QQ 重启/清缓存后失效（`NATIVE_STICKER_NOT_IN_CACHE`）。`native-stickers.js` 的 `sendSavedStickerFile()` 在失败时把 `data/sticker-images` 里的原图转 `base64://`，经 `sender.sendForwardedImage` 走完整管道（限频/去重/留档）发出去；`sender.js` 的该入口现在接受两种来源，指纹改 `sha256` 定长（base64 不能直接当 key）。核心侧实测 `base64://` 发送返回 `message_id:943221434`。
- **不连续发同一张**：`native-stickers.js` 的 `lastStickerByChat` + `pickDifferentSticker()`——同一会话刚发过的那张，下一轮点名它时自动换成库里另一张（只改"选哪张"，档位/授权/频控不动）；库里有且只有这一张时照发。五个用例（无历史 / 有别的 / 只有一张 / 换另一张 / 反向）全部通过。
