## 开发目的

此前一直关注并使用开源项目 SnowLuma 进行学习与实验。在 SnowLuma 创作者收到腾讯律师函并将仓库转为私有后，为了延续个人的技术探索与日常使用需求，决定汲取相关经验，动手构建一套更轻量、更贴合个人使用习惯的全新接入框架 **Alcor**，并在此基础上编写了主打低门槛与易用性的智能体程序 **Alcor Agent**。

## 项目简介

本项目由底层协议接入框架 **Alcor** 与上层智能体应用 **Alcor Agent** 协同驱动，致力于以**低门槛、易上手、轻量化**的方式打通大语言模型与 QQ 即时通讯生态：

* **Alcor**：基于 NapCat 与 SnowLuma 的设计经验重新开发的 QQ 接入框架，专注于简化配置流程与降低部署门槛，提供清晰的消息收发、事件分发与账号状态管理能力。
* **Alcor Agent**：运行在 Alcor 框架之上的 AI 智能体核心，集成意图决策、记忆管理、插件调度与可视化数据查询，让 AI 能够以自然拟人的方式操作 QQ 账号进行日常聊天。

## 核心特性

* **简单易上手，开箱即用**：摒弃繁琐的配置与复杂依赖，致力于让新手也能在短时间内完成部署并跑通完整的 QQ AI 对话流程。
* **纯粹免费，零内购**：项目本体完全免费提供，不包含任何功能付费墙、会员订阅或隐藏内购项目（用户仅需自备合规的大模型 API 密钥即可运行）。
* **极简插件与 Skill 扩展**：提供极其直观、低上手门槛的自定义插件（Plugin）与技能（Skill）接入机制，无需复杂脚手架即可快速赋予 AI 联网查询、群管自动化或外部工具调用等新能力。
* **高度可定制的 AI 人设**：支持灵活配置角色设定、语言风格与行为边界，轻松打造贴合特定群聊氛围或个人偏好的专属智能体形象。
* **运行数据清晰可查**：内置完善的透明化查询能力，支持随时查看详细的 **API 用量信息**、完整的**历史会话记录**以及结构化的 **AI 记忆存档**，让每一次模型调用与记忆演变都有迹可循。
* **协议与智能双层解耦**：底层通信（Alcor）与上层逻辑（Alcor Agent）独立分层，结构清晰，方便后续扩展与二次开发。

## 快速开始

1. 安装正式版安装包（Windows x64），或按下文的开发方式从源码运行。
2. 首次启动后打开控制台 `http://127.0.0.1:5320`，在 **设置 → 模型与联网** 填入自己的大模型 API 地址与密钥，保存后点「测试连通性」。
3. 在 **设置 → 聊天与人格** 写好人设、管理员 QQ、聊天白名单与回复档位。
4. 在 **设置 → 连接与桌面** 连接 OneBot / 启动内置 Alcor 核心，即可开始收发消息。

开发运行（需要 Node 22+）：

```bash
cd resources/app
npm install
npm start
```

## 控制台显示「无法连接 / 被占用」怎么办

程序不自带任何第三方框架（NapCat、SnowLuma、LiteLoader 都不在包里，见 `resources/alcor/native-core/discovery.mjs` 只做识别）。遇到连不上：

**先点 设置 → 连接与桌面 → QQ 接入 →「一键检测并连接」**。它会自己启动核心、拉起 QQ、清理残留宿主、重试注入，并把每一步写在卡片上；未登记的 QQ 版本可以点「仍然尝试注入」试一次（失败会自动重启 QQ 恢复原状）。

要看完整报告，双击安装目录里的：

`控制台无法连接，显示被占用点这个，对照最后一行判定码.cmd`

它只读地扫一遍本机（系统版本、QQ 进程、注入器、宿主 DLL、运行库、权限、会话、安全策略、上次失败阶段），**最后一行是判定码**，按下面的表处理。完整报告同时落盘在 `data/qq-doctor-<时间戳>.log`。

| 判定码 | 含义 | 处理 |
| --- | --- | --- |
| `ALREADY_CONNECTED` | 已连上 | 无需处理 |
| `READY_TO_CONNECT` | 一切就绪 | 点「连接 QQ」或「一键检测并连接」 |
| `RECEIVE_NOT_READY` | 宿主连上了，账号或消息通道还没确认 | 确认 QQ 已登录后点「重新扫描」；一直不恢复就重启 QQ 再连 |
| `CORE_OFFLINE` | Alcor 核心没在运行 | 侧栏「Alcor」页启动核心，再回来连接 |
| `NO_QQ_RUNNING` | 没检测到 QQ 进程 | 先登录 QQ；一键连接会自己帮你拉起 |
| `UNSUPPORTED_BUILD` | QQ 版本未适配，且没有可直接尝试的进程 | 换回已适配版本（`9.9.36-53644` / `9.9.37-54395`），或以普通权限启动 QQ 后再扫描 |
| `QQ_BUILD_UNLISTED` | QQ 构建未登记，但可以试 | 点「仍然尝试注入」：兼容模式试一次，失败会自动重启 QQ 恢复原状 |
| `HOST_PRESENT` | 上次注入的宿主还驻留在 QQ 里 | 等半分钟让它自己接回，或点「重启 QQ 后重试」 |
| `HOST_ALREADY_PRESENT` | 注入时发现模块已在 QQ 里 | 一键连接会先关干净 QQ 再重开，然后重试 |
| `FOREIGN_MODULES` | 有其他框架占用 | 一个号只能接一个框架；退出 LiteLoaderQQNT / NapCat / LLOneBot / SnowLuma 等，报告会列出模块名 |
| `ELEVATION_MISMATCH` | QQ 与 Alcor 权限不一致 | 两边用同一种权限（都不提权最省事），或点「以管理员重启」 |
| `SESSION_MISMATCH` | QQ 与 Alcor 不在同一个 Windows 会话 | 在同一登录会话里打开两者（别一个远程桌面、一个本机控制台） |
| `ARCH_MISMATCH` | QQ 不是 64 位 | 换装官方 64 位 QQ（安装包默认 x64） |
| `HOST_RUNTIME_BROKEN` | 注入器或宿主 DLL 缺失/损坏 | 重新安装；或装 VC++ 运行库后重启 Alcor |
| `HOST_TARGET_DENIED` | 加载器拿不到 QQ 进程操作权 | 多为权限/受保护进程；按 `ELEVATION_MISMATCH` 处理后再试 |
| `HOST_LOAD_BLOCKED` | alcor-host.dll 在 QQ 里加载失败 | 安全软件加白名单（Alcor 目录与 QQ 目录）；关闭「内核隔离 · 内存完整性」后重启；确认是 64 位 QQ |
| `HOST_ENTRY_FAILED` | DLL 进去了但没起来 | 重启 QQ 再试；仍失败请把 `data/qq-doctor-*.log` 发回来 |
| `INJECTION_BLOCKED` | 环境主动拦截注入 | 检查 HVCI、智能应用控制、EDR；按提示逐项放开后重启 |
| `PROCESS_UNREADABLE` | 读不到 QQ 进程信息 | 用管理员身份运行一次排查程序；或检查安全软件是否拦了进程查询 |

同一份判定也显示在 **设置 → 连接与桌面 → QQ 接入** 卡片上，底栏状态会写成「QQ 版本未适配」「QQ 可以连接」这类短语。


## 版本

当前版本 **Alcor Agent 0.3.2**（安装包 `Alcor-Agent-Setup-0.3.2-x64.exe`，正式版，Releases 页可下载）。

本版要点：

* **内核升级到 Alcor 核心 0.3.1**：任意 QQ 版本自适应注入 —— 内建表命中零改动；未登记的构建会现场扫描推导 14 个 RVA，生成成对的宿主 DLL 与注入器放到位，跨进程建包互斥、缓存四道校验。已用 9.9.33-51802 / 9.9.33-52230 / 9.9.35-52892 / 9.9.36-53644 / 9.9.37-54395 五份真实 wrapper 验证。
* **更新通道修好**：装了代理或加速器（Clash fake-ip）时不再被 SSRF 防护误拦；点「立即更新」不再出现「安装器一闪而过」；多源清单按发布时间择优，不会被 CDN 旧缓存压住。
* **安装器不再误杀进程**：全新安装不再结束正在运行的其他程序与 QQ；覆盖升级只结束目标目录自己的实例，且只在文件确实被占用时动手。
* **小版本提醒**：之后的修复走小版本补丁（`0.3.2-as.N`），只替换同一条更新通道里的安装包，客户端最多 20 秒就能轮询到并自动安装，不需要重新下载大版本。仓库文件列表里的 `update/manifest.json` 与 `update/notes.md` 始终是最新一次发布的内容。
