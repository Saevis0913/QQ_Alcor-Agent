# Alcor Agent v0.2.1

Alcor Agent 基于 QQ Agent（Kondius，MIT）修改，安装包内置 Alcor 自有原生核心、控制台、Electron 和 Node.js。原作者及第三方许可证随包保留。

当前已真实验证原生群/私聊文字、图片接收、视频抽帧、群语音与 TXT、普通/嵌套转发媒体，以及 QQ 空间本人和好友正文读取。任意媒体上传发送、私聊文件和部分原生通知仍未完成；完整范围见 开发目录 docs/acceptance-20261114.md 中的验收记录。本轮改动已部署到 D:\Alcor，尚未重新生成安装包。

## 安装与首次使用

1. 运行 Alcor-Agent-Setup-0.2.1-x64.exe。默认安装在 D:\Alcor，也可选择其他可写目录；可创建桌面和开始菜单快捷方式。
2. 向导集中显示缺失项、错误代码和修复建议。必须修复项会阻止安装；QQ、模型和白名单可在安装后配置。点击“复制完整报告给本地 AI”即可提交排错信息。
3. 打开安装目录的 Alcor Agent.exe 或桌面快捷方式。首次启动生成独立本地令牌，选择空闲且互不冲突的 Agent/核心端口，默认暂停且白名单为空。
4. 正常登录 QQ，在 Agent 的 Alcor 页点击“打开控制台（免输令牌）”，选择已登录进程接入。按 wrapper.node 的 SHA-256 精确匹配：QQ 9.9.36-53644 x64 已实测；QQ 9.9.37-54395 x64 已静态适配，待实际运行验证。其他模块会明确报告不兼容，不能只凭版本号判断。
5. 设置模型 API、聊天白名单和回复方式，再点击“恢复”。模型可使用云端兼容服务或本地 AI 服务。

环境基线为 Windows 10 2004 / Windows 11 x64，或对应较新的 Windows Server x64，及 Windows PowerShell 5.1。运行时已随包提供，不需要另外安装开发工具。建议至少预留 1.5 GB，并给聊天记录/附件留出额外空间。实际安装验证使用 Windows 11 x64；其他机器仍以环境检测结果和实际验证为准。

## 回复与外观

回复方式为：不回复、只回复 @、按 0.1–99.9% 概率回复、全部回复。私聊在“只回复 @”下保持安静；文本中的 @昵称不算群内提及。“不回复”也阻止定时提醒及尚未发出的排队内容，被抑制的提醒保留待发。已提交给 QQ 的消息无法撤回。白名单、暂停和限流仍有效。

保留峰谷时间与人设管理。左侧主导航不减少功能；可选择日间白紫、夜间黑紫或按时间切换。技能/插件添加页可复制包含实际安装路径的开发提示词，开发规范见 doc/extend_development。

“设置 → 管理员”支持填写多个 QQ，保存后立即生效。管理员和特殊好友免每日私聊额度，但不自动加入白名单，也不获得本地执行或群管理权限。私聊额度按收到的好友消息计算，机器人回复不计入，重复推送只计一次，北京时间零点重置；0 表示不限。新好友首条、暂停及名单过滤时收到的消息也计数，界面已有明确说明。

QQ 空间只读取近期本人/好友动态，按条目去重并共用每日额度。正常重启可恢复加密保存的登录态；服务端使其过期后需重新登录。管理员可在私聊查询当天本地快照，不会向空间发表、评论或点赞。

## 数据与诊断

程序数据存放在安装目录的 data 下，技能与插件位于 resources/app/skills 和 resources/app/plugins。覆盖安装前从托盘退出 Agent。覆盖安装和卸载保留用户配置、聊天数据及自定义扩展；更换机器时先备份这些内容，不要公开密钥。

Agent 的 Alcor 页提供安装导航与环境检测；程序打不开时运行安装目录的 Diagnose-Alcor.cmd，完整报告写入 data/environment-report.txt，可复制给本地 AI 排查。现有配置格式损坏时停止启动并保留原文件，不用空配置替换它。

“检查更新”接口已实现，但正式更新源尚未配置；目前没有自动下载安装，也没有新的已签名发行包。原生核心不依赖其他 QQ 消息后端，普通 QQ 客户端仍是运行前置项。本轮安装包与正式发布继续暂缓。
